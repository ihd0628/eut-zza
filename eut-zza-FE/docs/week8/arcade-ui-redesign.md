# 읏짜 아케이드 UI 리디자인

## 방향

1990년대 후반~2000년대 초반 리듬게임의 각진 프레임, 금속 패널, 굵은 제목과 숫자 표시를 참고한다.
기존 게임의 로고나 이미지를 복제하지 않고 읏짜의 레코드 그래픽과 4레인 아이콘을 사용한다.

- 배경: 차콜 블랙. 선택: 보라. 시작 버튼·주요 점수: 옐로.
- 스캔라인은 메뉴 장식에만 사용한다. 실제 게임 레인에는 노트 가독성을 우선한다.
- 영어 제목은 분위기를, 한국어 설명·버튼은 동작을 전달한다.
- 정적 스타일은 각 컴포넌트의 CSS Module에 둔다. 전역 CSS는 토큰과 reset만 담당한다.

## 화면 구조

- 로그인: 로고·레코드 그래픽과 계정 입력 영역을 분리.
- 모드 선택: 솔로 / 2~4인 멀티플레이의 두 선택 패널.
- 곡 선택: 왼쪽 곡 목록·랭킹, 오른쪽 선택 곡·난이도·시작 버튼.
- 방 목록: 행 단위 목록과 자동 매칭 영역.
- 대기실: 네 개의 고정 슬롯. 빈자리, 방장, 준비 상태를 구분.
- 결과: 최종 점수·판정·순위. 멀티플레이는 방 대기실로 복귀.

## 게임 화면과 React / Canvas 경계

데스크톱은 `내 점수·콤보 | Canvas 레인 | 실시간 순위` 3열이다.
솔로의 오른쪽에는 곡 그래픽을 표시한다. 작은 화면에서는 내 점수가 상단으로 이동한다.

`GameCanvas`는 솔로·멀티플레이가 공유하는 게임 화면이다.
곡명, 난이도, 선택적인 오른쪽 패널을 받아 배치한다.
GameEngine의 기존 `onProgress`를 받아 HUD를 갱신하고, 멀티플레이의 기존 전송 콜백에도 전달한다.

- HUD 갱신: 노트 판정이 발생할 때.
- 노트 이동: 기존 GameLoop와 CanvasRenderer, AudioContext 시간 기준.
- 인스턴스: 기존 ref에 보관. HUD 렌더링이나 순위 업데이트로 재생을 다시 시작하지 않는다.
- Canvas 내부 좌표: 480×720 유지. 화면에 보이는 크기만 CSS로 높이에 맞추고 2:3 비율을 유지.
- 판정선 위치, 노트 속도, 판정·점수 계산, 서버 공통 시작 시각과 결과 제출 정책은 변경하지 않는다.
- 게임 중 일반 헤더·로그아웃을 숨겨 플레이 공간을 확보한다.
- 실시간 순위는 최종 결과와 구별하고 동점은 같은 순위로 표시한다.

## 검증 범위

- FE TypeScript / production build / lint.
- 로컬 Chrome + Playwright로 주요 화면 및 반응형 배치 확인.
- API·WebSocket 응답은 테스트 데이터로 대체. 운영 서버·DB는 사용하지 않는다.
- 실제 로컬 MP3를 내려받고 Web Audio로 재생하여 Canvas 이동과 키 입력 후 HUD 갱신 확인.
- 4인 실시간 메시지로 순위 갱신, 준비 상태, 최종 결과에서 대기실 복귀 확인.
- 운영 환경의 실제 여러 사용자 간 회귀 검증은 별도로 진행해야 한다.

브라우저 검증용 스크린샷과 로그는 검증 후 삭제한다.
